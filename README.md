# お薬管理

毎日の服用と在庫を記録する、スマートフォン向けのアプリです。iPhone の Safari で開いて「ホーム画面に追加」すると、普通のアプリと同じようにホーム画面から起動できます。このような、ウェブページをアプリのように使える仕組みを PWA（Progressive Web App）と呼びます。

データはサーバーには送られず、使っている端末の中（ブラウザの localStorage という保存場所）だけに保存されます。一度開けば、電波が届かない場所でも起動できます。

## できること

「今日」タブでは、今日飲むお薬が朝・昼・夜の順に並びます。「飲んだ」を押すと記録が付き、その分だけ在庫が自動で減ります。週1回のお薬は、予定の曜日を過ぎてもまだ使っていなければ「未実施」として表示され続けます。在庫が7日分を切ると、警告が表示されます。

「今日」タブのいちばん上には、次回の通院日までの日数が表示されます。カードを押して通院日（必須）と時刻・病院・メモ（任意）を登録すると、「あと29日」のように表示され、前日は「明日です」、当日は「今日です」に変わります。通院日の前日までに在庫（自宅と実家の合計）が足りなくなりそうなお薬があれば、「○○があと9錠たりません」のように知らせます。通院日の登録も端末の中だけに保存され、バックアップには一緒に書き出されます。

「今日」タブの「リスト｜カレンダー」のボタンで、今日の一覧と月カレンダーを切り替えられます。カレンダーでは、各日に朝・昼・夜・週1回の丸印が並び、全部飲んだ日は濃い色、一部だけなら薄い色、まだなら白い丸で表示されます。日付を押すとその日の画面が開き、「まだの分を全部まとめて記録」や「朝をまとめて記録」のボタンで、朝・昼・夜の分をまとめて記録できます。過去の日の分は、朝8時・昼12時・夜19時に飲んだものとして記録されます。記録した分を取り消すときも、「朝をまとめて取り消す」や「この日の記録を全部取り消す」のボタンでまとめて取り消せます。どちらも確認が出てから取り消すので、うっかり押しても大丈夫です。最後に選んだ表示は覚えておくので、次に開いたときも同じ表示になります。

間違えて「飲んだ」を押したときは、すぐに出るお知らせの「取り消す」を押すと、記録が消えて在庫が元に戻ります。お知らせが消えたあとでも、ボタンが「済み」になった項目を押せば、確認のうえで取り消せます。

「お薬」タブでは、登録したお薬の在庫と、あと何日分残っているかを確認できます。補充・編集・削除・並び替えもこのタブで行います。

「記録」タブでは、直近7日または30日の服用率のグラフと、予定どおり飲めた日が何日続いているか（連続達成）を確認できます。飲み忘れて記録しなかった分をあとから追加したり、記録を直したり取り消したりすることもできます。

右上の歯車からは、バックアップの書き出しと読み込み、全データの削除ができます。

### 自宅と実家の在庫

お薬の在庫は「自宅」と「実家」の2か所に分けて管理できます。「今日」タブの上にある「今いる場所」で、今どちらにいるかを選んでおきます。「飲んだ」を押すと、選んでいる場所の在庫が減ります。選んだ場所は覚えておくので、場所を移ったときだけ切り替えれば大丈夫です。

「お薬」タブでは、場所ごとの残りと、その分だけであと何日もつかが表示されます。補充するときは、どちらの場所に足すかを選べます。自宅から実家へお薬を持っていったときは「移動」を使うと、合計の数は変えずに置き場所だけを入れ替えられます。今いる場所の在庫が1日分以下になると、「今日」タブに知らせが出ます。

服用の履歴には、どちらの場所で飲んだかも残ります。場所を間違えて記録したときは、履歴から直せます。この機能を足す前の記録や在庫は、すべて自宅の分として扱います。

## フォルダの構成

アプリを直すときに触るのは `src/` と `public/` の2つです。`dist/` はビルド（後述）で自動的に作られるので、直接は編集しません。

```
src/                 アプリのソースコード
  App.jsx            アプリ全体のまとめ役（データを持ち、各画面に渡す）
  screens/           各タブの画面（今日・お薬・記録）
  components/        入力フォームやシートなど、画面の部品
  lib/               計算やデータ保存の処理（画面とは独立していてテストできる）
    schedule.js      「今日飲むもの」と服用率・連続達成の計算
    records.js       服用の記録・在庫の増減・お薬の登録などのデータ書き換え
    storage.js       端末への保存とバックアップの形式
    medicine.js      タイミングや単位などの決まりごと、在庫日数の計算
    date.js          日付の道具
  styles.css         画面全体の見た目の設定
public/              そのまま公開されるファイル（index.html、アイコン、sw.js など）
tests/               計算処理のテスト
scripts/build.mjs    ビルドの手順
dist/                公開用のファイル一式（ビルドで作られる）
```

## 開発のしかた

あらかじめ Node.js（JavaScript をパソコンで動かすためのソフト）の 18 以上をインストールしておきます。そのうえで、このフォルダで次のコマンドを実行します。

```sh
npm install      # 必要な部品を取ってくる（最初の1回だけ）
npm run dev      # 直すたびに自動で作り直し、http://localhost:5173 で確認できる
npm test         # 計算処理のテストを実行する
npm run build    # 公開用のファイルを dist/ に作る
```

ここでいう「ビルド」とは、`src/` に分けて書いたソースコードを、ブラウザがそのまま読み込める1つのファイル（`dist/app.js`）にまとめる作業のことです。画面の見た目を決める CSS も、使っている分だけを集めて `dist/tailwind.css` にまとめます。

## 公開のしかた

アプリは GitHub Pages で公開しています。GitHub Pages は、GitHub のリポジトリの中身を無料でウェブサイトとして公開できる仕組みです。公開先のアドレスは https://syuritakuma.github.io/okusuri/ です。

`main` ブランチに変更が入ると、GitHub Actions（GitHub 上で決まった作業を自動で行う仕組み）が、テストとビルドを行ってからサイトを自動で更新します。手順は `.github/workflows/pages.yml` に書いてあります。テストが1つでも失敗した場合は公開されないので、壊れた版が公開されることはありません。公開の進み具合は、リポジトリの「Actions」タブで確認できます。

最初の1回だけ、リポジトリの設定で GitHub Pages を有効にする必要があります。「Settings」→「Pages」を開き、「Build and deployment」の「Source」を「GitHub Actions」にしてください。

ほかのサーバーに置きたい場合は、`npm run build` を実行してから、`dist/` の**中身のファイル**をすべて、公開先の同じ場所に並べて置きます。フォルダごとではなく、`index.html` と同じ階層に `app.js` や `tailwind.css` が並ぶように置いてください。

ビルドのたびに、ファイルに「版番号」が書き込まれます。端末は一度読み込んだファイルを保存して使い回しますが、版番号が変わると新しいファイルを取り直すため、更新が確実に反映されます。

## データの引き継ぎ

端末への保存場所の名前（`med_app_medicines_v2` と `med_app_logs_v2`）は、作り直す前の版と同じです。バックアップファイルは、自宅と実家の在庫を入れるために形式を version 3 にしましたが、以前の version 2 のファイルも読み込めます。同じアドレスで公開すれば、今までの記録もそのまま使えます。

## 注意

このアプリは服用の記録を助けるための道具です。服用量や飲み方については、必ず医師や薬剤師の指示に従ってください。
